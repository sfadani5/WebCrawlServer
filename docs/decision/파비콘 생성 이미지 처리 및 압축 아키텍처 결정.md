# 파비콘 생성 이미지 처리 및 압축 아키텍처 결정

> **Rule ID**: 해당 없음 (ADR)
> **분류**: 기록·운영·보관 (R-005xx)
> **작성일**: 2026-08-03
> **상태**: 채택
> **작성자**: Mistral Vibe

---

## 배경

관리자 대시보드에 파비콘 생성 유틸리티 기능을 추가하면서, 다음과 같은 기술적 결정이 필요했다:

1. **클라이언트 사이드 vs 서버 사이드 처리**: 파비콘 생성은 서버와 관계없는 독립적 유틸리티로 요청되었기 때문에, 서버에 의존하지 않는 순수 클라이언트 사이드 구현이 필요했다.
2. **이미지 리사이징 방법**: 다양한 크기(16x16, 32x32, 48x48, 180x180, 192x192, 512x512)의 파비콘을 생성하기 위한 이미지 처리 방법이 필요했다.
3. **ZIP 압축 방법**: 생성된 모든 파일을 하나의 ZIP으로 묶어 다운로드하기 위한 압축 방법이 필요했다.
4. **ICO 파일 포맷**: 다중 크기를 포함한 ICO 파일 포맷 처리 방법이 필요했다.

---

## 결정

### 1. 클라이언트 사이드 구현

**결정**: 모든 이미지 처리 및 압축을 **클라이언트 사이드에서만 수행**한다.

**이유**:
- 요청 사항에서 "서버와 관계없이 독자적인 유틸리티"로 명시됨
- 서버 리소스 사용하지 않음 (서버 부하 없음)
- 네트워크 송신 없음 (보안 및 성능 우수)
- 오프라인에서도 동작 가능

### 2. 이미지 리사이징 - HTML5 Canvas API

**결정**: **HTML5 Canvas API**를 사용하여 이미지 리사이징을 구현한다.

**구현 방법**:
```typescript
const canvas = document.createElement('canvas');
canvas.width = targetWidth;
canvas.height = targetHeight;
const ctx = canvas.getContext('2d');

ctx.imageSmoothingEnabled = true;
ctx.imageSmoothingQuality = 'high';

// 비율 유지하며 중앙 정렬
const ratio = Math.min(targetWidth / sourceWidth, targetHeight / sourceHeight);
const newWidth = sourceWidth * ratio;
const newHeight = sourceHeight * ratio;
const x = (targetWidth - newWidth) / 2;
const y = (targetHeight - newHeight) / 2;

ctx.drawImage(image, x, y, newWidth, newHeight);
const dataUrl = canvas.toDataURL('image/png');
```

**이유**:
- 브라우저 기본 API로 추가 라이브러리 불필요
- 모든 모던 브라우저에서 지원
- 고품질 다운샘플링 가능 (`imageSmoothingQuality: 'high'`)
- 메모리 효율적 (Canvas는 자동으로 정리됨)

### 3. ZIP 압축 - JSZip 라이브러리

**결정**: **JSZip 라이브러리**를 사용하여 ZIP 압축을 구현한다.

**구현 방법**:
```typescript
import JSZip from 'jszip';

const zip = new JSZip();
zip.file('favicon-16x16.png', blob, { binary: true });
// ... 모든 파일 추가

const content = await zip.generateAsync({ type: 'blob' });
const url = URL.createObjectURL(content);
// 다운로드 링크 생성
```

**이유**:
- 클라이언트 사이드 ZIP 생성 표준 라이브러리
- Promise 기반 비동기 처리 지원
- 모든 모던 브라우저 호환
- ESM 지원 (TypeScript 및 Vite 환경과 호환)
- 작고 가벼운 라이브러리 (약 30KB min+gzip)

### 4. ICO 파일 처리 - 단순 PNG 변환

**결정**: **ICO 파일은 48x48 PNG를 .ico 확장자로 저장**한다. (완전한 ICO 포맷 변환은 보류)

**이유**:
- ICO 포맷은 바이너리 구조가 복잡하여 구현 비용이 높음
- 대부분의 모던 브라우저는 PNG 파일을 ICO로 인식가능
- 실제 사용 시 48x48 PNG가 대부분의 경우 호환성 문제 없음
- 필요 시 후속 작업으로 완전한 ICO 포맷 변환 구현 가능

## 대안 고려

### 이미지 리사이징 대안

| 방법 | 장점 | 단점 | 결정 이유 |
|------|------|------|-----------|
| **HTML5 Canvas API** | 기본 API, 추가 의존성 없음, 고품질 | 구현 필요 | ✅ 채택 |
| Sharp 라이브러리 | 고품질, Server-side | 서버 의존성, Node.js 환경 필요 | ❌ 서버와 무관한 유틸리티임 |
| Browser-image-compression | 간편한 사용 | 추가 라이브러리, 파일 크기 증가 | ❌ 기본 API로 충분 |
| Web Worker | 백그라운드 처리 | 구현 복잡성 증가 | ❌ 현재 성능 이슈 없음 |

### ZIP 압축 대안

| 방법 | 장점 | 단점 | 결정 이유 |
|------|------|------|-----------|
| **JSZip** | 표준 라이브러리, Promise 지원 | 외부 의존성 | ✅ 채택 |
| zip.js | 기능 풍부 | 파일 크기 큼 (100KB+) | ❌ JSZip이 더 가벼움 |
| manually ZIP | 의존성 없음 | 구현 매우 복잡 | ❌ 유지 보수 어려움 |
| 서버 측 압축 | 서버 리소스 사용 | 서버 의존성 | ❌ 요청 사항 위반 |

## 결과

### 장점

1. **완전 클라이언트 사이드**: 서버에 아무런 부담 없이 동작
2. **고품질 이미지**: Canvas API로 고품질 리사이징 보장
3. **빠른 처리**: 모든 작업이 브라우저에서 즉시 수행
4. **오프라인 지원**: 인터넷 연결 없이도 사용 가능
5. **조작 간편**: 드래그 앤 드랍 인터페이스로 사용자 편의성 우수

### 단점

1. **ICO 포맷 제한**: 완전한 ICO 포맷 지원만이 아직 미비
2. **대용량 이미지**: 매우 큰 이미지의 경우 브라우저 메모리 사용 증가
3. **브라우저 호환성**: 일부 오래된 브라우저에서 Canvas API 제한적 지원

### 성능 고려사항

- **이미지 크기 제한**: 최소 16x16 픽셀 requirement
- **메모리 관리**: Canvas 객체는 자동으로 garbage collected
- **비동기 처리**: 모든 리사이징 작업을 Promise.all로 병렬 처리
- **ZIP 생성**: 비동기 처리로 UI 블로킹 방지

## 후속 작업

1. **완전한 ICO 포맷 지원**
   - 현재: 48x48 PNG를 .ico 확장자로 저장
   - 개선: 실제 ICO 바이너리 포맷 구현 (16x16, 32x32, 48x48 다중 레이어)
   - 우선순위: 중 (호환성 요구 시)

2. **이미지 최적화**
   - PNG 최적화 (PNG-8 또는 WebP 포맷 변환)
   - 파일 크기 최적화 알고리즘 도입
   - 우선순위: 낮

3. **프리셋 추가**
   - 여러 파일 형식의 프리셋 추가 (예: favicon only, mobile only 등)
   - 사용자 정의 크기 지원
   - 우선순위: 낮

4. **배치 처리**
   - 여러 이미지를 한 번에 업로드하여 배치 처리
   - 우선순위: 낮
